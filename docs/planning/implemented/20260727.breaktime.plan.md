# Screen Break: non-blocking breaks (other timers stay usable)

**Status:** draft for review — 2026-07-27
**Branch:** `feature/break-multitimer`, from `integration` (plain feature branch; no worktree — solo task)

## Goal

Today a Screen Break freezes the whole device: `TIMER_BREAK` is the active slot's state, Button A is refused, and Button C (swap timer) is refused outright — so a kid on a 15 min eye-rest break cannot go and run the Piano or Violin timer, which is exactly what the break time is for.

After this change the break still **enforces** the Screen timer (no early resume, screen time stays frozen, the break countdown is absolute wall time), but it no longer blocks the other timers: Button C works during a break, the selected extra timer starts/pauses/expires normally, and the break runs down in the background with a visible cue on the panel.

## Behaviour spec

Worked examples (from the request):

| # | Scenario | Expected |
|---|---|---|
| 1 | Break 15 min starts; kid swaps to Piano (5 min) and runs it | Piano alert fires at T+5. Break-over chime fires at T+15. Two separate alerts, in that order. |
| 2 | Break 15 min starts; kid swaps to Piano (15 min), starts it ~1 min in | At T+15 the break ends **silently** (Piano is RUNNING). Only Piano's expiry alert fires, at T+16. |

Rules that fall out of those, plus the corner cases resolved during review:

1. **Break is enforced for Screen only.** With Screen selected and slot 0 in `BREAK`, Button A stays refused (unchanged). Button B remains the ParentTesting escape (unchanged).
2. **Button C is allowed during a break** and becomes an EXT1 wake source again (the mask is rebuilt from `timer_swap_allowed()` at every sleep entry).
3. **Extra timers behave normally during a break** — start, pause, expire, alert, reload. Eye-rest accrual is Screen-only and does not run during a break, so a break can never start while an extra timer is selected.
4. **Break-over chime is suppressed when any extra slot is RUNNING at the moment the break ends.** (Literal rule, per review — accepts the rare double-alarm when an extra timer expires a few seconds *before* the break does.) In every other case (extra timer IDLE/PAUSED/EXPIRED, or Screen selected) the chime fires as today.
5. **The chime and the return to Screen are the same event.** Whenever the break-over chime fires and an extra timer is selected, the selection snaps back to slot 0 (Screen) and the panel repaints the Screen main layout in `PAUSED` — the pre-multi-timer behaviour of "break expires, you're back on your screen timer". When the chime is suppressed (an extra timer is RUNNING) the selection is left alone: stealing it mid-run would be hostile, and the kid gets back to Screen with Button C. `EXPIRED` counts as not-RUNNING here, so a finished Piano also snaps back.
6. **A late-observed break end never chimes and never snaps.** If the transition is first observed more than `BREAK_CHIME_GRACE_SEC` (75 s — see [Chime grace window](#chime-grace-window)) after the break's wall end (charge lock, bed-time lock, power cycle, long sleep) it lands silently — the chime is an "it just happened" signal, not a replay.
7. **Screen returns to `PAUSED` at break end** exactly as today; Button A resumes it (immediately, when rule 5 snapped the selection back).
8. **Day rollover** resets everything including a live break (unchanged).

Geometry notes that must hold (`display.c` `CLEAN_BANDS` contract — bands must not share a framebuffer byte):

- The chip is 16 pt at `y=3` → rows 3..20 as built (measured off the golden bitmap in review; this estimate originally read 3..21) → bytes 0..2, which is exactly the header band's byte range (rows 3..17 → bytes 0..2). The next band starts at byte 3 = row 24, so no byte is shared. **No band edit needed and no other widget moves**, so no existing golden changes except the break screen.
- The break screen's bottom row packs three 16 pt items into rows ~106..126: `Screen h:mm` left at x=4 (~99 px → 4..103), the swap hint centred over button C (x=165, name truncated to 8 chars → ~129..201), and the refresh symbol over D (x=239). 12 pt is unusable white-on-black on this panel (existing comment in `display_screens.c`), hence 16 pt throughout and the truncation budget.
- When no extra timers are configured, the break screen keeps today's centred `Timer paused - 1:30:00 left` footer and no button row.

## Design

### State model change

Keep `TIMER_BREAK` as slot 0's state and `break_expiry_wall` in slot 0 — no new RTC fields, no snapshot version bump. What changes is the invariant:

> **Old:** only the ACTIVE slot can be `RUNNING` or `BREAK`.
> **New:** only the active slot can be `RUNNING`; **slot 0 may be in `BREAK` while any slot is active.**

Every `timer_*` helper that reads break state via `active()` must therefore read slot 0 explicitly. This is the whole risk surface of the change and it is confined to `timer.c`.

#### State truth table (test contract)

The combination space widens, so Task 2 encodes it as a **table-driven test** rather than prose — one case per row, each asserting every column. `k` = any enabled extra slot.

Structural invariants (asserted in a shared helper called after every mutation in the suite, so no test can leave an illegal state behind):

| # | Invariant |
|---|---|
| I1 | `BREAK` only ever appears on slot 0 |
| I2 | at most one slot is `RUNNING` at any time |
| I3 | a `RUNNING` slot is always the active slot |
| I4 | `break_expiry_wall != 0` **iff** slot 0 is `BREAK` |
| I5 | slot 0 `BREAK` ⇒ slot 0 `remaining_at_pause` is the frozen screen time (never consumed by an extra slot's run) |

Behaviour table (the rows the suite must cover):

| slot 0 | active | active state | `swap_allowed` | `break_active` | `break_remaining` | Button A | chime at break end | snap to Screen |
|---|---|---|---|---|---|---|---|---|
| `BREAK` | 0 | `BREAK` | true¹ | true | > 0 | refused | yes | n/a (already Screen) |
| `BREAK` | k | `IDLE` | true¹ | true | > 0 | starts k | yes | yes |
| `BREAK` | k | `RUNNING` | **false** | true | > 0 | pauses k | **no** | **no** |
| `BREAK` | k | `PAUSED` | true¹ | true | > 0 | resumes k | yes | yes |
| `BREAK` | k | `EXPIRED` | true¹ | true | > 0 | none | yes | yes |
| `PAUSED` (post-break) | k | `RUNNING` | false | false | 0 | pauses k | n/a | n/a |
| `RUNNING` | 0 | `RUNNING` | false | false | 0 | pauses | n/a | n/a |
| `IDLE` | k | any | per state | false | 0 | per state | n/a | n/a |

¹ subject to `timer_extra_count() > 0`, as today.

Transition cases on top of the table: `timer_break_tick` fires its edge exactly once (second call returns false), reports `overdue_sec`, and leaves the active extra slot untouched; `timer_shift_expiry` moves the active RUNNING expiry **and** slot 0's break expiry with no double-shift when slot 0 is active; snapshot round-trip preserves slot 0 `BREAK` + `active_slot = k`.

### Two pending events

With a break running behind a RUNNING extra timer there can be two future events. Resolution:

- If an extra slot is RUNNING, the break end is **silent** (rule 4) → it needs **no dedicated wake and no stay-awake watch**. It lands at whatever the next tick wake is, and the chip disappears there.
- If nothing is RUNNING, the break end **will** chime → the planner gets it as a secondary event and the awake watch owns the tail, exactly as today.

So `sleep_plan_in_t` gains one optional secondary event and `main.c` only populates it when the chime is pending. Suppression can only change via a button press, which is a wake and therefore a re-plan.

### Chime grace window

**Why a grace at all.** The break end is an absolute wall time. On the healthy path the planner wakes ~70 s before it (`SLEEP_PLAN_EVENT_LEAD_SEC`) and the awake watch fires the chime within ~1 s of the true end. But three paths deliberately stop doing timer work and only notice the transition on their next wake:

| Path | Sleep interval | Worst-case lateness |
|---|---|---|
| Charge lock (≤ 10 % battery) | `CHARGE_LOCK_SLEEP_SEC` 600 s | 10 min, or hours if the pack stays low |
| Bed-time lock | `BEDTIME_SLEEP_SEC` 7200 s | 2 h |
| Power cycle / panic (RTC wiped) | n/a — snapshot restore | unbounded |

Without a bound, the first wake after any of those chimes for something that ended two hours ago, at 6 am, with nobody there. The snapshot-restore path already dodges this by converting an elapsed `BREAK` straight to `PAUSED` silently (`timer.c:580`), so a grace makes the other paths consistent with it rather than inventing a new policy.

**How late is "legitimately late".** Every path that *should* chime observes the transition either inside the awake watch (~1 s) or on the very next tick wake (~60 s max, the normal minute cadence). The suppressed-then-unsuppressed case cannot sneak past that either: un-suppressing means pausing the extra timer, which is a button press, hence a wake and a re-plan. Nothing legitimate lands between one minute and ten, so the bound only has to separate "next tick" from "a lock intervened".

**Decided:** `#define BREAK_CHIME_GRACE_SEC SLEEP_PLAN_WATCH_SEC` (75 s = `SLEEP_PLAN_EVENT_LEAD_SEC + 5`). That constant already means "close enough to the event that the firmware owns it", so the rule reads as *chime only if we were inside the watch window for it* — derived rather than magic, and it still clears the 60 s tick cadence with 15 s of margin. Rejected: a bare `2 * 60` (a chosen number with no derivation), and a flag set by the charge-lock/bed-time-lock release paths (extra RTC state, couples the locks to the break, and still misses the power-cycle case).

Host-tested in `test_timer` via `overdue_sec` (the value `timer_break_tick` reports), with cases at 0 s, 60 s, grace−1, grace+1.

### Module changes

| Module | Change |
|---|---|
| `main/timer.c` / `include/timer.h` | break reads/writes target slot 0; new `timer_break_active`, `timer_break_tick`, `timer_any_extra_running`, `timer_next_slot`, `timer_select_screen`; `timer_swap_allowed` drops the BREAK refusal; `timer_shift_expiry` also shifts slot 0's break expiry |
| `main/sleep_plan.c` / `.h` | `sleep_plan_in_t.break_remaining_sec` secondary event lead |
| `main/wake_policy.c` / `.h` | `wake_policy_render` gains `break_ended` so the wake that drops the chip (and may snap back to Screen) forces a full refresh |
| `main/bedtime.c` / `.h` | `bedtime_should_alert(state, break_active)` — a background break still counts as "interrupted something" |
| `main/app_state.c` | fills `break_remaining_sec` from slot 0, plus new `break_banner` + `swap_next_name` |
| `include/display.h` | `display_state_t` += `bool break_banner`, `const char *swap_next_name`; new pure formatters |
| `main/display_layout.c` | `display_format_break_chip()`, `display_format_swap_hint()` |
| `main/display_screens.c` | header chip; break-screen bottom row |
| `main/main.c` | `handle_break_end()` helper replaces the two inline chime checks (chime + snap-back + render promotion in one owner); generalised `watch_break_end`; planner input |
| `main/stats_json.c` / `.h` | `break_remaining_s` in the stat payload + two HA entities |
| `main/mqtt_ha.c` | `DISC_SCHEMA_VER` 13 → 14 (new entities do not appear otherwise) |
| docs | `ProductOverview.md` §5a/§6/§6a/§7, `architecture.md` invariant + notes |

### Rejected alternatives

- **Break as a device-level field outside the slot array** — cleaner conceptually, but rewrites the snapshot layout (version bump, migration) for no behavioural gain.
- **Deferred chime** (fire the break-over chime when the running timer later expires) — rejected in review: the kid is already getting that timer's alert.
- **Strict-lock config flag** to keep today's behaviour — out of scope per review.

- [ ] **Tests first** (`test/test_timer/test_timer.c`):
