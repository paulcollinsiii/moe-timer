# break-swallows-expiry: implementor notes

Status: implemented, uncommitted, gates run (see the final report).

## Structure

- Decision: `wake_flow_expire_or_break()` (static, `main/wake_flow.c`, right
  after `wake_flow_fire_expiry_alert`). It calls `wake_flow_maybe_start_break(now)`
  and, if that accepts, owes the expiry publish and returns; otherwise it
  fires the plain expiry alert. `maybe_start_break` already declines for
  interval 0 and for a balance short of the interval, so no separate policy
  function was needed (it would have duplicated those two checks).
- Break end: `wake_policy_render` no longer alerts when `before == TIMER_BREAK`
  (BREAK -> EXPIRED is timer.c I7's restore). This was a live defect for any
  break over an already-EXPIRED slot 0, not only for swallowed ones.
- Budget: `WAKE_FLOW_FINAL_ALARM_MS` = max(expiry alarm, break alarm) replaces
  the expiry-only term in `WAKE_FLOW_FINAL_MINUTE_WORST_MS`. Default figure
  unchanged (15.1 s expiry > 7.6 s break). `test/CMakeLists.txt` gained
  `CONFIG_MAGTAG_BREAK_ALARM_CYCLES=3` for test_wake_flow.

## Decisions 6 and 7

- Persistence: no extra save before the break. `wake_flow_maybe_start_break`
  persists BREAK before the paint and alarm, and a BREAK snapshot over an
  EXPIRED slot 0 restores BREAK (then EXPIRED once the wall end has passed):
  `test_exact_tie_break_over_an_expired_slot_survives_a_reset_and_ends_expired`.
  The bed-time branch engages the lock itself (no return).
- Publish: `wake_flow_owe_publish()` after the break's paint and alarm, served
  by each caller's own consumer (all unchanged).

## Behaviour notes

- After a swallow the wake carries on like it does after the expiry alert
  (not an immediate sleep): the tails handle a BREAK state (watch_break_end
  returns for a long break). Same as the expiry path it replaces.
- Existing tests changed: row9 poll/interval counts (+1 question at the
  expiry), row4 matrix (BREAK -> EXPIRED does not alert).

## Fix pass 2 (second review: M1, M2, m1, m2, nit)

- M1: `timer_run_accum` (main/timer.c) ends the live segment at the wall of
  the RUNNING slot that armed it when that wall is behind `now`. The break
  gates read it before the tick. Probe A reads 2700 / not due (was 3000 /
  due); probe B 1600 (was 1720).
- M2: `expire_slot_at(slot, fold_at)` is the primitive; `expire_slot` (the
  natural, late-discovered wall: min(now, wall)) wraps it, with a comment
  saying the reading is sound only because no other path leaves a past wall.
  `adjust_core`'s RUNNING arm and `timer_reconcile_def` expire at `now`
  themselves when they move the wall to <= now (fold at now). Probes C 300
  (was 100), C2 400 (was 900), D 300 (was 100). A deduction that leaves the
  wall ahead just moves it; the late natural expiry folds at that wall.
- Signatures: `timer_adjust(slot, sec, now)`, `timer_bonus_reconcile(slot,
  target, now)`. `timer_release_gated(sec)` is unchanged: it is grant-only
  (unsigned owed seconds) and passes now = 0, which can never take the
  immediate-expiry branch. Production callers: only `net_apply_finish`.
- Alarm trace: before, an HA deduction past zero left RUNNING with a past
  wall and the next tick (repaint_after_join's RUNNING -> EXPIRED diff, or
  the next wake's tick) raised TIME'S UP. Now the edge happens inside
  `net_apply_finish`, where no later tick sees it, and a caller that ignores
  the result (`net_apply_try_window_then`) would lose the alarm entirely.
  So `net_apply_finish` announces it exactly like a reconcile's expiry
  (`on_active_expired_alert` once, return ALERTED, so repaint_after_join does
  not fire a second). Accepted difference: that is the plain alert, so a
  deduction expiry that coincides with a break-due tie is not swallowed by
  the break (the stance this file already takes for reconcile). Tests are in
  test_net_apply (alerts once; a deduction that leaves time does not alert;
  a bonus on a running Screen).
- Test shims: the ~100 arithmetic-only callers in test_timer, test_app_state
  and test_net_apply go through a function-like macro at T0; clock-pinning
  tests call `(timer_adjust)(slot, sec, now)`.
- m1: decision 7 in the plan and the fast-path code comment record the
  relaxation (owed publish lost at the immediate sleep; the next sync
  carries it, per 20261016.stats-publish-events).
- m2: pinned in test_timer: extra swallow (expired once, break end returns
  to it EXPIRED, no re-expiry), second `timer_start_break` returns false
  (completions 1), snapshot restore after a swallow (no double count).
- Nit: the wake_flow.c budget comment now says 161.5 s at 7 break cycles
  (break path 16.4 + 4 = 20.4 < 24.0). The Fix pass 1 line above quoting
  161.9 s is the same slip.
