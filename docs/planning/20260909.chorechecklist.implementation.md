# Chore checklist — implementation plan

**Audience:** the orchestrator coordinating implementor → reviewer → fix cycles.
**Scope:** what to build, in what order, and what "done" means. All *why* lives
in the design doc and is referenced, never restated.

**Design doc:** `20260909.chorechecklist.md` (approved). References below are
`design §N`. An implementor should read only the sections its task cites.

**Branch:** `feature/chore-checklist` off `integration`.

---

## 0 · Ground rules

Applies to every task. The reviewer enforces these on every cycle.

| Rule | Detail |
| --- | --- |
| **TDD** | Tests first for every layer-1/pure module, and for `chores.c`, `schedule.c`, `timer.c`, `display_layout.c` specifically (CLAUDE.md priority list). A cycle that lands implementation before its test is rejected. |
| **`main/main.c`** | **Zero additions.** M0-T1 *removes* four lines; nothing in this plan adds any. Any diff touching main.c must name one of the four residency reasons or be rejected outright. |
| **Formatting** | `.c`/`.h` must pass `clang-format --dry-run --Werror`. Auto-fix with `clang-format -i`. |
| **Commits** | Conventional Commits, enforced by the commit-msg hook: `<type>[(<scope>)]: <desc>`. |
| **Goldens** | `MAGTAG_WRITE_GOLDEN=1` rewrites **every** golden. Regenerate, then `git checkout` the ones that were not meant to change. Three legacy goldens carry a stray trailing byte — do not "fix" them in an unrelated task. |
| **Golden honesty** | A golden is regenerated only for an intended layout change. Never to make an unexpected diff pass. The reviewer checks that each regenerated golden is named in the task. |
| **`sdkconfig`** | Generated and gitignored. M0-T1 removes a symbol from it — diff against `sdkconfig.bak` after any regen to confirm the hand-set values (MQTT creds, timer names) survived. |
| **Layering** | New modules land in the layer the task names. A layer-1 module that reads the clock, NVS or GPIO is rejected. |
| **Parallelism** | Two tasks touching the same file never run concurrently. The Depends column is the authority. |

### Verification

```bash
# host tests — the gate for every task
cmake -S test -B test/build && cmake --build test/build \
  && ctest --test-dir test/build --output-on-failure

# firmware build — the gate for every milestone
source ~/esp/esp-idf/export.sh && idf.py build

# goldens, when a task says so
MAGTAG_WRITE_GOLDEN=1 ctest --test-dir test/build -R display_render
```

### Definition of done (every task)

1. Tests written first, and failing, before implementation.
2. Host suite green.
3. `clang-format` clean.
4. Reviewer cycle passed; fixes applied by a separate fix agent.
5. Committed with a Conventional Commit message naming the task ID.

**Reviewer focus for M2**

- `M2-T2`: the rejection to hunt for is an **early return** into a chore-screen handler. That shape stranded the break-end latch once already. Verify `timer_break_take_ended` is still drained on a wake that paints the chore screen.
- `M2-T3`: A must not be a wake source when its press could only be refused.
- `M2-T5`: px/sec must be uniform across the boundary; a rescaled free tranche silently changes the bar's meaning.
- `M2-T8`: `neopixel_stop_sync()` on **every** path to sleep, including the failsafe. A left-on power gate is a battery bug that only shows up in the field.
- `M2-T9`: the 1 s driver guard is untouched. Any change under `components/ssd1680/` in this task is a rejection.
- `M2-T10`: this is the **third** device lock. Verify the release path — a device that cannot leave this screen is unrecoverable without a cable.
- `M2-T11`: **the review note the row above points at.** Three things are worth
  carrying forward from it, because none was a coding error:
  1. **The help text overclaimed the hardware.** A first draft said "a board
     swept it and 400 is what came back", which contradicted this very
     document. What a board established was a **lower bound** — 250 is too
     short; 400 is §2.5's pre-existing prose estimate and **nobody has swept
     it**. When board time settles one end of a range, say which end.
  2. **An invariant was asserted as a mechanism with nothing holding it**, and
     its stated consequence ("the host suites and the firmware are timing two
     different devices") was **unreachable** — the `#else` fallback is
     compiled by no host suite, proved by mutating it and watching every test
     still pass. That one was answered by **building the gate**
     (`scripts/check-ack-hold-default.py`) rather than softening the sentence,
     which is the right direction whenever the infrastructure already exists.
  3. **A figure recorded at N sites, updated at a subset.** The ack hold lived
     in 5 places and the pixel-order claim in 3 (`include/neopixel.h`,
     `main/neopixel.c` and `main/status_led.c` — the third found by neither
     the brief nor the review). This is the **same shape M2-T10 was about**,
     recurring one task later, which argues it is a property of the codebase
     rather than a lapse: grep for the value before editing any comment that
     states one.

- `M2-T12`: **the note the row above points at**, and the most instructive
  failure in the milestone, because nothing was coded wrong.
  1. **The original defect was a header comment that promised what the
     arithmetic could not deliver.** `button_latch.h` said the debounce
     covered "contact chatter on press plus falling-edge bounce on release".
     The first half was true; the second could never be, because the window
     is anchored on the press edge and a hold is of unbounded length. This is
     the milestone's signature defect in its most expensive form — not a
     comment that went stale, but one that was **false when written**, and
     believed by every reader for the whole of M1 and M2 precisely because it
     named the exact failure mode it did not prevent.
  2. **It was latent for a reason worth remembering.** The phantom edge was
     always generated and always discarded, by a bare latch drain nobody
     thought of as protection. M2-T8 inserted the ack coalescer *above* that
     drain, and a defect that had never had a consumer suddenly had one. The
     bug was introduced **by exposure**, not by the new code being wrong —
     so "what did I put in front of an existing discard?" is a question
     worth asking of any new consumer on a latch or queue path.
  3. **The obvious fix would have made it worse.** Counting presses per
     button — which is what the symptom "repeat presses don't register"
     suggests, and what this orchestrator recommended — layered on top of a
     double-latching edge source would have promoted an intermittent wrong
     answer into a reliable one: every press toggling twice. The lesson is
     to fix the edge accounting *before* anything downstream counts edges.
  4. Alternatives rejected on hardware-risk grounds and recorded in the code:
     `GPIO_INTR_ANYEDGE` plus a level read **in the ISR** would call a
     flash-resident driver function from an `IRAM_ATTR` handler, which is the
     shape of the USB-CDC sleep panic; and ANYEDGE plus edge *parity*
     desynchronises for the rest of the wake on one long bounce train. A

- **The config-publishing automation is the owner's confirmed-working one**
  (it replaces the To-do bridge in `docs/home_assistant.md`). It is committed

  `todo.magtag_<node>_chores`: the id the automation looks for. Renaming the
  list later keeps the id. The tab embeds HA's todo-list card for it, so
  chores are edited where everything else about that device is.
