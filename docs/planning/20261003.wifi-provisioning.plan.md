# On-device WiFi + MQTT provisioning

Status: **task 0 done** (results below; D1 resolved with no guard move and no
font work). Task 1 next.
Branch: `feature/wifi-provisioning`, to be cut from **`integration`**.
Baseline: `integration` at `3fd02d1`. Line references are against that
revision.
Motivation: ship one firmware image with no credentials baked in; the owner
enters WiFi and MQTT on the device, and can come back later to add or change
either.

## Goal

1. A device whose NVS holds no WiFi SSID boots into **setup mode**: it brings
   up a SoftAP and runs ESP-IDF's provisioning manager, and the e-paper shows
   what the owner needs to join.
2. The owner provisions WiFi with Espressif's stock phone app, and enters MQTT
   broker details through the same session.
3. A provisioned device can be put back into setup mode on demand: a **long
   press of the BOOT button**. This covers "WiFi first, MQTT later" with no
   Home Assistant link.
4. Build-time WiFi and MQTT credentials are **removed**. `credentials.local.h`
   and menuconfig stop carrying them.

Non-goals: BLE provisioning (the ESP32-S2 has no Bluetooth), a custom phone
app, provisioning the OTA URL or any HA-managed field (HA stays the editor for
those once MQTT is up), and a partition-table change.

## Constraints found in the code

| --- | --- | --- | --- |

| C6 | `esp_restart()` zeroes every `RTC_DATA_ATTR` | memory note; `main/main.c:380` flushes the timer snapshot before the OTA restart | Leaving setup mode must not need a restart, or must use the same flush-then-restart path. |
| C7 | GPIO0 (BOOT) is unused; buttons A–D are GPIO 15/14/12/11 on EXT1 `ANY_LOW` | `main/buttons.c:23-26`, `:304` | BOOT can join the EXT1 mask (GPIO0 is RTC-capable on the S2). |

## Design

### Components

- **`espressif/network_provisioning`** (the IDF 6 managed component that
  replaced the in-tree `wifi_provisioning`), scheme **SoftAP**, security
  **2** (SRP6a). It provides the Espressif "ESP SoftAP Prov" app flow, the AP
  scan list, and a real STA join attempt. A bad password is reported back to
  the app instead of being stored.
- **`esp_http_server`**: pulled in by the SoftAP transport. The app creates
  the httpd instance itself and hands it to the scheme
  (`network_prov_scheme_softap_set_httpd_handle`), so it can also register its
  own URIs (below).
- **LVGL's built-in QR widget** (`LV_USE_QRCODE`) to draw the provisioning QR
  payload on the panel. This avoids adding `espressif/qrcode`.

### How MQTT credentials get in

The stock Espressif apps collect **WiFi only**. A custom protocomm endpoint can
carry MQTT, but no stock app UI fills one in. Plan:

- **Primary:** a small static HTML form served from the same httpd at
  `http://192.168.4.1/mqtt`. Fields: broker URI, username, password.
  - URI and user are prefilled from NVS. The password is never echoed; blank
    means keep the current one.
  - It is reachable only on the setup SoftAP, whose WPA2 password is random
    per session and shown on the panel.
- **Secondary (cheap, same handler logic):** a custom endpoint `mqtt-config`
  taking the same fields as JSON. This lets `esp_prov.py --custom_data`
  script it.

The form posts to a **host-tested validator** (lengths match the getters'
buffers: URI < 128, user/pass < 64; scheme must be `mqtt://` or `mqtts://`).
That code goes in `config_validate.c`, or beside it if that file's scope does
not fit.

### Entering setup mode

| Trigger | Behaviour |
| --- | --- |
| No WiFi SSID in NVS (fresh device, or credentials cleared) | Enter setup automatically on cold boot and on any button wake. |
| BOOT pressed while awake, or pressed to wake, then **held ≥ 5 s** | Panel shows "Release to enter setup" at the threshold; releasing enters setup. A shorter press does nothing. |
| WiFi joins keep failing | **Not** an automatic trigger. A router outage would otherwise turn every wake into a SoftAP session and drain the battery. The status line instead says "WiFi failing — hold BOOT for setup". |
| MQTT URI empty but WiFi set | **Not** a trigger. A WiFi-only device is a supported state. |

The BOOT hold is timed by the firmware after boot, so strapping (C8) is never
involved. **Open hardware check:** confirm on the bench that holding GPIO0 low
*across a deep-sleep wake* does not enter download mode. The expectation is
that strapping is latched only on chip/system reset, not on a deep-sleep wake.
If it does enter download mode, BOOT is used only while awake (any A–D press
wakes first).

### The setup session

1. Extend the awake failsafe through the existing op to a setup budget
   (proposed Kconfig `MAGTAG_SETUP_MAX_SEC`, default 600, bounded).
2. Generate a per-session SoftAP password and an SRP6a verifier (security 2
   username/PoP). Render the setup screen: AP name (`MagTag-<device_id>`),
   AP password, QR payload, and the form URL.
3. Run the provisioning manager plus the MQTT form handler until one of these:
   - **WiFi provisioned and the join verified** → copy SSID/pass into the
     app's NVS keys (D3). If MQTT details were also submitted, store them.
     Stop the manager, render "Setup complete", and continue (D4).
   - **MQTT-only submit on a device that already has WiFi** → store, end the
     session the same way.
   - **Budget expires** → render "Setup timed out — hold BOOT to retry" and
     deep-sleep. With no SSID, the device wakes on buttons only, so an
     unprovisioned device in a drawer does not cycle the radio.
4. While in setup, no MQTT session, NTP, OTA check or tick runs. Setup is its
   own wake outcome, not an `app_mode_t`, so `APP_MODE_TIMERS == 0` and
   `RTC_STATE_VERSION` are untouched unless D4 says otherwise.

### Removing build-time credentials

- Delete the five rows from `NVS_SEEDED_STRS`, the `NVS_DEFAULT_WIFI_*` /
  `NVS_DEFAULT_MQTT_*` fallbacks, and Kconfig `MAGTAG_MQTT_URI/USER/PASS`.
- **Migration is free:** removing the rows changes the defaults fingerprint,
  so the first boot after the update runs one reseed. That reseed writes only
  the remaining rows, the holidays blob and a cleared `cfg_ver` (HA re-applies
  its retained config on the next window). The stored `wifi_*` and `mqtt_*`
  keys are **not** in the registry any more, so they survive. An in-service
  device keeps working without re-provisioning.
- Remove `test_fingerprint_folds_in_credentials`
  (`test/test_nvs_config/test_nvs_config.c:226`). Add a test that a reseed
  leaves pre-existing credential keys untouched.

## Decisions

| # | Decision | Recommendation |
| --- | --- | --- |
| D1 | 85 % build guard vs the measured size delta | **Resolved by task 0:** the LVGL widget and pixel-format trims freed 128 KB, so provisioning fits at 82.6 % with the guard unchanged. Font subsetting and `CONFIG_LWIP_IPV6=n` remain in reserve. |
| D2 | MQTT entry path | Form page primary, `esp_prov.py` endpoint secondary (above). |
| D3 | Credential source of truth | Keep the **app's NVS keys** and copy into them when provisioning succeeds. `wifi_session.c`, `nvs_config` and their tests stay as they are, and the driver's store remains a transient. Clear the driver's stored config after the copy so the two cannot disagree. |
| D4 | How setup ends | No `esp_restart` (C6). Stop the provisioning manager, deinit the SoftAP, and deep-sleep with a 1 s timer wake into a normal network window. That window is the first real join, NTP sync and HA discovery. |
| D5 | Long-press threshold | 5 s, with on-panel confirmation at the threshold. |
| D6 | HA "enter setup" button entity | Out of scope. It only helps a device that already has MQTT, and it would need a `STATS_JSON_DISC_SCHEMA_VER` bump. Revisit later. |

## Risks

- **Flash:** provisioning measured at 112 KB, which leaves 44 KB under the
  guard after the LVGL trims for tasks 3–5's own code. If that runs out, the
  reserves are: the `esp_stdio` +23 KB, the fonts' 61 unused icon glyphs (an
  estimated 65–80 KB) and IPv6.
- **Internal RAM during setup:** SoftAP plus httpd plus SRP run in internal
  RAM with only 7 KB of static DIRAM spare. Setup runs instead of the
  MQTT/TLS/OTA window, never alongside it, so peak heap should sit below the
  OTA download's. Task 7 measures it.
- **Battery:** a SoftAP session is the most expensive thing the device will
  do. The budget is bounded by the failsafe, and the timeout sleeps
  buttons-only.
- **Security:** the form is plain HTTP, protected by the per-session WPA2 AP
  password shown only on the panel. WiFi provisioning itself is
  SRP6a-protected. Credentials are never echoed back.
