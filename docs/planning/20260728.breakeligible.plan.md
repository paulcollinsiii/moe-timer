# Break-eligible timers — multiple "screen" activities

Status: draft for review
Branch: `feature/break-eligible`
Predecessor: `20260727.breaktime.plan.md` (non-blocking Screen Break, merged as `92823c5`)

## Problem

The non-blocking Screen Break lets the kid run Piano or Violin during a break.
That is the point of it. But not every extra timer is a genuine break from a
screen: "Laundry folding" is a chore done *with the TV on*. Running it during
an eye-rest break defeats the break, and running it outside a break accrues
real screen exposure that today is invisible to the break scheduler.

So an extra timer needs to declare whether it is a legitimate break activity.

## Decisions (settled in discussion, 2026-07-28)

| Decision | Choice |
| --- | --- |
| Flag name | `break_eligible` (per-timer bool) |
| Polarity | `true` = valid during a Screen Break. Laundry folding is `false`. |
| What it gates | **Startability, not selection.** Every timer stays reachable by Button C; a non-eligible one simply cannot be started while a break runs. |
| Screen-break accrual | A non-eligible timer's RUNNING time accrues toward the break interval. |
| Daily allocation | **Not** debited by non-eligible timers. Accrual tracks eye exposure; allocation tracks entitlement. A chore should not cost TV budget. |
| Break entry | The active timer is forced to PAUSED; selection snaps to slot 0 (break screen). |
| Break exit | Selection returns to the slot the break interrupted, **only when nothing is running**. |

## The model

The unifying idea: **slot 0 is itself `break_eligible = false`.** Screen time is
the original non-eligible activity. Laundry folding is a second one. That
collapses what looks like two systems into a single rule:

> **Screen-exposure accrual advances whenever the active slot is RUNNING and
> not `break_eligible`. A Screen Break refuses to start any slot that is not
> `break_eligible`.**

No special-casing of slot 0 in the accrual path, and the existing eye-rest
behaviour falls out unchanged.

### Where the accrual lives

Keep `run_accum_sec` / `run_started_wall` on **slot 0** and let non-eligible
extras drive slot 0's fields. Slot 0 *is* the screen, so this is coherent, and
it costs nothing new:

- `timer_shift_expiry` already shifts `run_started_wall` for every slot
  (`main/timer.c:505`), so NTP correction generalises for free.
- The crash-recovery snapshot already carries both fields
  (`main/timer.c:585`), so no version bump for the accrual change.

The cost is that `timer_run_accum` currently keys off `sl->state ==
TIMER_RUNNING` on the *active* slot (`main/timer.c:424`). That has to become
"exposure is active", which is true when the active slot is RUNNING and not
`break_eligible` — slot 0's own state may be IDLE or PAUSED while Laundry runs.

## Behaviour rules

1. `break_eligible` is a compile-time default (Kconfig) overridden by the
   HA-managed NVS blob, exactly like `reloadable`.
2. Slot 0 ("Screen") is permanently `break_eligible = false`. It is not
   configurable.
3. Accrual advances while the active slot is RUNNING and not break-eligible.
4. A break may become due while slot 0 is IDLE or PAUSED — the kid can fold
   laundry for the whole interval without ever starting Screen.
5. On break start: the active timer is forced to PAUSED, the interrupted slot
   is recorded, selection snaps to slot 0, the break screen is shown.
6. During a break, Button A is refused on any non-eligible slot. The ▶ glyph is
   not drawn, matching the existing "label shows iff a press would work"
   convention (`main/display_screens.c:203`).
7. During a break, every slot remains reachable by Button C. Swapping to
   Laundry shows its screen and remaining time; it just cannot be started.
8. On break end: chime unless a break-eligible timer is RUNNING (unchanged),
   then return selection to the interrupted slot — only if nothing is running.
9. Slot 0's break-exit state is **PAUSED if `remaining_at_pause > 0`, else
   IDLE**. Derived, not stored.

## Structural invariants

Carried forward from the predecessor plan, extended:

- **I1** Only the active slot can be RUNNING.
- **I2** `TIMER_BREAK` lives on slot 0 only.
- **I3** Slot 0 may be in BREAK while any slot is active.
- **I4** Break helpers read slot 0 explicitly, never the active slot.
- **I5** `timer_break_tick()` latches the end edge; `timer_break_take_ended()`
  consumes it once. Both idempotent.
- **I6** *(new)* A non-break-eligible slot is never RUNNING while slot 0 is in
  BREAK. Guaranteed by rules 5 and 6 — this is what keeps
  `wake_policy_break_chime()` honest without changing it.
- **I7** *(new)* Slot 0 exits BREAK to PAUSED iff `remaining_at_pause > 0`,
  otherwise IDLE.
- **I8** *(new)* Screen-exposure accrual advances iff the active slot is
  RUNNING and not `break_eligible`.

## Behaviour table (TDD contract)

| # | Active slot | Its state | Break | Event | Outcome |
| --- | --- | --- | --- | --- | --- |
| 1 | Screen | RUNNING | none | accrual crosses | Screen → BREAK; selection stays 0; break screen. *(today)* |
| 2 | Laundry | RUNNING | none | accrual crosses | Laundry → PAUSED; slot 0 → BREAK; interrupted = Laundry; selection → 0 |
| 3 | Laundry | RUNNING | none | expiry **and** accrual cross in one tick | expiry alert first, then break starts; interrupted = Laundry |
| 4 | Piano | IDLE/PAUSED | active | press A | starts normally |
| 5 | Laundry | IDLE/PAUSED | active | press A | refused; ▶ not drawn |
| 6 | Screen | BREAK | active | press A | refused *(today)* |
| 7 | Screen | BREAK | ends | nothing running, interrupted = Laundry | chime; selection → Laundry (PAUSED) |
| 8 | Piano | RUNNING | ends | — | no chime, no snap *(today)* |
| 9 | Screen | BREAK | ends | interrupted = Screen | chime; selection stays 0 *(today)* |
| 10 | Screen | BREAK | ends | Screen never started today | slot 0 → **IDLE**, not PAUSED (I7) |
| 11 | Laundry | RUNNING | none | Laundry expires at accrual threshold | fold segment, then break becomes due with nothing running |

Rows 2, 3, 5, 7, 10, 11 are new and must be written as tests before the
implementation.

## Display

No new screens. Three deltas:

**Main screen, non-eligible timer during a break.** The break chip already
renders in the header (predecessor plan). The only change is the missing ▶:

```
┌────────────────────────────────────────────┐
│ Mon 28 Jul  14:32          [ BREAK 6:12 ]  │   ← inverted chip, existing
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░  │
│              12:30                    87%  │
│ Laundry folding — Paused                   │
│        Reset          →           ⟳        │   ← no ▶ on button A
└────────────────────────────────────────────┘
```

**Break screen swap hint.** The hint must reflect whether a *startable* timer
exists, not merely another enabled slot. If Laundry is the only extra, the
break offers nothing and the hint is suppressed — the break then behaves like
the pre-`92823c5` locking break, which is correct.

**Golden files.** `main_break_chip.bin` gains a no-▶ variant; a new
`break_screen_no_eligible.bin` covers the suppressed hint. Regenerate only
these (see the `MAGTAG_WRITE_GOLDEN` caveat — it rewrites every golden, so
check the untouched ones back out).

## New persistent state

One byte, and it is the only place the "no new state" instinct does not hold:

```c
uint8_t break_interrupted_slot;  /* slot active when the break started */
```

Rule 8 needs it — once the selection snaps to 0 at break start, nothing else
records what was interrupted. It lives in `rtc_state_t` and therefore bumps the
crash-recovery snapshot version (v5 → v6). Restore validation must reject a
value ≥ `TIMER_SLOT_COUNT`.

## Migration cost

`TIMER_DEFS_BLOB_VERSION` goes 1 → 2 (`include/nvs_config.h:83`). Version or
size drift reads as stale and falls back to the Kconfig table
(`main/timer_defs.c:56`), so **every device with HA-edited timer names or
durations silently reverts to the compile-time table on first boot after
flash.** Hand-set `sdkconfig` names come back correctly; anything edited from
Home Assistant afterward is lost. Acceptable for a single-device deployment,
but it should be a deliberate call, not a surprise.

`DISC_SCHEMA_VER` in `main/mqtt_ha.c` must also be bumped or the new per-timer
toggle will not appear in Home Assistant.

## Hardware smoke test

1. Fold-only break: Screen never started, run Laundry past the interval →
   break fires, Laundry pauses, break screen shown.
2. Break end from (1) → chime, selection returns to Laundry, **slot 0 shows
   IDLE not PAUSED** (I7, row 10).
3. Classic break: Screen running past the interval → unchanged from `92823c5`.
4. Break interrupts Laundry with Screen time banked → break end returns to
   Laundry; Screen still PAUSED with its remaining intact.
5. During a break, swap to Laundry → screen visible, no ▶, Button A does
   nothing.
6. During a break, swap to Piano → starts normally.
7. During a break, start Piano then let the break end → no chime, no snap
   (row 8), Piano keeps running.
8. Only-non-eligible config: disable Piano/Violin, leave Laundry → break screen
   shows no swap hint.
9. Deep-sleep crossing: start the break, let the device sleep through it, wake
   after the end → chime + correct snap target survive the snapshot.
10. Second break in one session driven entirely by laundry time.

## Open / deferred

- **Loophole**: with no allocation debit, the kid can park on "Laundry folding"
  and watch TV indefinitely. The eye-rest break still fires every interval,
  which is the health guard; the rest is parental supervision. Revisit only if
  it happens in practice.
- **Bedtime**: `bedtime_break_would_cross` (`main/main.c:559`) is evaluated at
  break start and is unaffected, but a non-eligible timer running into bedtime
  has not been considered. Likely wants the same handling as screen time.
- **Per-timer accrual reset**: a break resets slot 0's accrual
  (`main/timer.c:451`). Confirm that is still right when the accrual was driven
  by a different slot — it should be, since the clock is global to screen
  exposure, but it deserves a test.
