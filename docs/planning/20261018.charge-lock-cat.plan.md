## Decisions — settled, do not re-litigate

1. **Run-length encoded, decoded straight into the paint.** Measured on this
   art: raw 1 bpp 1,708 B, byte-run RLE 863 B, nibble RLE 921 B, row-XOR+RLE
   889 B, zlib 631 B. RLE wins: the screens already paint 1-bit art as
   horizontal runs of `lv_draw_rect` (`qr_draw_cb`, `main/display_screens.c`),
   so an RLE sprite is that run list read from flash — no scratch buffer.
   zlib (ROM `tinfl`) is rejected: ~11 KB of decoder state for 230 B saved.
2. **Encoding** (the measured 863 B one): the whole image as one row-major
   scan, runs alternating colour starting with **background**, one byte per
   run. A run longer than 255 is written as `255, 0, <rest>` (a zero-length
   opposite run continues the same colour). Runs wrap across rows; the
   decoder splits them at row ends.
3. **A generator, not hand-written data.** `tools/gen_sprites.py` (PEP 723,
   pillow, run with `uv run`, see `tools/gen_ha_dashboard.py` for the house
   style) reads every `tools/sprites/*.png` and writes
   `main/sprite_data.c` + `include/sprite_data.h` (one `const sprite_t` per
   PNG, named from the file: `SPRITE_CHARGE_CAT`). The generated files carry
   a "generated by tools/gen_sprites.py, do not edit" banner, are
   clang-format clean as generated, and are committed. A `--check` mode exits
   non-zero when the committed C does not match the PNGs.
4. **Decoder module** `main/sprite.c` / `include/sprite.h`, pure C with no
   LVGL: `sprite_t { uint16_t w, h; const uint8_t *rle; uint16_t rle_len; }`
   and an iterator that yields each **ink** run as `(x, y, len)` within one
   row. Malformed data (runs overrunning `w*h`, truncated stream) must stop
   cleanly, never read or paint past the end. `display_screens.c` gains a
   draw callback (shaped like `qr_draw_cb`) that paints those runs.
5. **Layout** per the mockup: cat at left, vertically centred; "Charge me!"
   and a nearly-empty battery outline (one bar) on the right. **No new LVGL
   font** (each costs KB of flash; enabled: 12, 16, 18, 28, 48). Use 48 if
   the words fit the right column with margin, else 28. Not inverted (thin
   lines). Full refresh only, so no `CLEAN_BANDS` entry, as today.
6. **Only the `charge_me` golden changes.** `MAGTAG_WRITE_GOLDEN=1` rewrites
   every golden: regenerate, then `git checkout` every other golden, and
   confirm `git status` shows only `charge_me.bin` changed under golden/.
   Add a fits-the-panel test (no ink in the outermost columns/rows), like
   `test_the_no_clock_screen_fits_the_panel`.
7. The main screen's "Charge Me!!!" warn badge is a different thing (the
   warn band) and is unchanged.
