# Screen break: meditating figure — plan

Owner request 2026-10-18: the SCREEN BREAK screen shows the owner's
meditating pixel-art figure. Approved mockup:
`20261018.break-meditate.mockup.png` beside this file (layout A). Third
sprite on the machinery from `20261018.charge-lock-cat.plan.md` (33b4922)
and `20261018.timesup-pikachu.plan.md`: reuse `tools/gen_sprites.py`,
`main/sprite.c` and the sprite draw callback — no second decoder or draw
path. Bed time is NOT approved and is out of scope.

## The art

`tools/sprites/break_meditate.png`, 46×52, 1-bit, black = ink (1,208 ink
pixels). Recovered by the coordinator from the owner's upscaled pixel-art
reference: box-downsampled to its native grid, the six sparkles (finer than
the figure's grid) re-stamped as 3×3 hollow diamonds. The reference is not
in the repo. Generates `SPRITE_BREAK_MEDITATE`. The PNG is placed in the
working tree uncommitted and is committed with the implementation, so no
commit has a PNG without its generated C (`--check` stays green per commit).

## Decisions — settled, do not re-litigate

1. **Drawn at 2×** (92×104 on the panel) for the chunky native-pixel look.
   Add an integer `scale` to the existing sprite draw path (each run becomes
   a `len*scale × scale` rect at `(x*scale, y*scale)`; the object is sized
   `w*scale × h*scale`); the cat and Pikachu keep scale 1 and their goldens
   must not change. Do not store a pre-scaled PNG.
2. **Inverted screen**, as today: the figure is WHITE ink on black, so the
   draw colour follows the screen (the callback must not hard-code black).
3. **Layout per the mockup**: figure at the left, x = 4, y = 4 (ends at
   y = 108, clear of the button row). Right column, centred in the space
   right of the figure: "SCREEN BREAK" Montserrat 18, countdown Montserrat
   48, the progress bar (outline + white fill, the right column's width),
   then the chores line. Button row unchanged.
4. **Countdown format** (coordinator default, owner did not object to the
   mockup): `m:ss`/`mm:ss` under one hour, `h:mm:ss` from one hour (breaks
   run to `CFG_BOUND_BREAK_DUR_HI` = 120 min). Test both sides of the hour
   boundary and the widest value (`1:59:59` or `2:00:00`) fits the column.
5. **Chores line stays Montserrat 16** — 12 px white-on-black is recorded in
   this file's comments as illegible on the panel. One line in the right
   column: "Chores 1 of 3" left, "Screen 1:30" right; if it does not fit at
   the widest values with a gap, shorten to "Chores 1/3" (measure, don't
   guess; a fit test pins it).
6. **All six break variants** keep their existing semantics (the
   has_chores / no-eligible / no-extras / all-done matrix and the button-row
   rules in `display_screens_build_break`'s comments) in the new layout.
   Their goldens are the ones that change: `break_screen*.bin` (6). Nothing
   else: `charge_me.bin`, `timesup.bin` and all main/setup goldens must be
   byte-identical to HEAD.
7. **Partial refresh**: this screen updates in place, and `display.c`'s
   `CLEAN_BANDS` table holds y-bands tied to the current break layout (read
   its comments first). Re-derive every band from the new geometry, keep the
   ghost-cleaning behaviour the comments require, and extend/adjust the
   tests that pin those bands. State in the notes which band covers which
   element. The figure is static between partials (never redrawn
   differently), so it needs no band of its own unless the tests say
   otherwise.
8. No new LVGL font (enabled: 12, 16, 18, 28, 48).
