# Stats publish on every timer event — plan

Owner request 2026-10-16: the HA burndown charts (`screen_remaining`,
`remaining_N`) should be accurate, which means a stats publish on every
event that moves them, and `screen_remaining` must not change meaning with
the timer state.

## What is wrong today

1. **`screen_remaining` changes meaning on a chore-gated day.**
   `app_state_stats()` (`main/app_state.c`) publishes
   `timer_slot_remaining(0, now, alloc)` with `alloc` the full day
   allocation. IDLE returns that fallback (e.g. 120 min) — but a start runs
   against the live cap `alloc − withheld` (`button_actions.c`
   `screen_cap`/`chore_withheld_now`, i.e. chore_free), so the published
   value drops the moment the timer starts, then jumps back up when the
   last chore releases the withheld block. Owner: "that makes for a
   confusing graph".
2. **Events that move the charts open no network window, so nothing is
   published until the next sync** (10 min while RUNNING, 60 min idle —
   `CONFIG_MAGTAG_RUNNING/IDLE_SYNC_INTERVAL_MIN`):
   - **Pause** — `BTN_B_PAUSED` arm of `wake_flow_dispatch_button_action`,
     and the awake pause poll (`wake_flow_poll_pause_button`, final-minute
     watch, grid wait).
   - **Expiry** — the expiry alert path. The last publish is the
     final-minute pre-expiry sync, so HA shows "N s left" for up to an hour.
   - **Chore release** — the `BTN_ACK_RELEASED` edge in
     `wake_flow_apply_chore_ack()` adds the withheld block, unpublished.
   - **Two rare starts** — (a) a press latched during a wake that already
     ran its sync window (`wake_flow.c` latched-press call with
     `!synced_this_wake`); (b) a press in the break tail
     (`wake_flow_poll_break_buttons`, whose render half runs after the
     window was joined).

## Decisions — settled (owner 2026-10-16), do not re-litigate

1. **`screen_remaining` is "available now".** IDLE on a gated day publishes
   `alloc − withheld` (the same cap a start would run against — reuse the
   one helper, do not re-derive it), so a start does not move the value and
   the only step up is the release, which is real. RUNNING / PAUSED /
   EXPIRED already reflect the cap. `screen_limit` stays the full effective
   allocation. Extra slots are unaffected (no chore gate). Correct every
   comment/doc that says "used is derivable: limit − remaining" or
   describes screen_remaining, grep the whole tree. The discovery payload
   does not change, so no `STATS_JSON_DISC_SCHEMA_VER` bump unless the
   implementation changes a discovery field.
2. **Publish (one network window, stats posted after the paint) on:** start
   and resume on every path including the two gaps above, pause on every
   path, expiry, and the chore-release edge. Every window that gets wifi up
   already publishes the full state, so "publish" means "open a window
   whose snapshot post comes after the paint"; do not add a second
   publisher.
3. **Cost is accepted:** one wifi+MQTT window (~5–10 s radio) per event.
   A wake that already has a window open for this event must not open a
   second one.

## Constraints

- **Power serialization**: radio TX must never overlap an e-ink refresh
  (existing rendezvous: snapshot posted after the paint) **nor the audio
  amp** — the expiry alert and the chore reward chime must finish before
  the window's TX begins (or the window must be opened after them). State
  in the review how each new window is ordered against paint and audio.
- **Awake budget**: any `_Static_assert` against the awake ceiling
  (`CHORE_WORST_GESTURE_MS`, expiry/final-minute budgets, `ota_timing.h`)
  must count the new window. Update the figures and every comment quoting
  them.
- **Pause stays immediate**: the pause is applied and painted first; the
  window comes after. A pause must never wait on NTP before painting.
- `main/main.c` gains no line (CLAUDE.md adversarial rule).
- The quiet hours/bedtime/locks gates are unchanged: if a path currently
  refuses network (e.g. a lock or a wifi-failure backoff), keep it refusing.
- TDD in `test_wake_flow` / `test_app_state` (or wherever these seams are
  tested): one test per event path asserting a window is opened and the
  snapshot is posted after the paint, one asserting no double window, and
  the gated-day IDLE value.
