## Design decisions (and why)

- **Where the gesture lives.** Only on the EXT1 wake press (`wake_flow_handle_button_wake`,
  `case BTN_C`, Timers mode). A latched C on a tick wake or in the break tail
  keeps today's single swap through `wake_flow_dispatch_button_action`: the
  plan says "wake press, or a latched one", but a latched press has no
  following presses to count and the break tail's poll loop returns on the
  first applied press by design. Recorded as a scope choice.
- **Per-button window.** Two arrays in the latch: the configured window (what the
  next accepted press opens) and the stamped window (what the last accepted
  press opened, which `record` compares against). Stamping means a change never
  reaches into a running window, and a SEEDED press always stamps the default.
  The seed is the wake press, which anchors at reset a boot after the press;
  nothing knows when its release rings, so it keeps the long window.
- **When the mode is known.** The latch is armed in `buttons_init` before
  the wake handler runs, so every window is the default then. The short window
  is installed by `wake_flow` when the gesture OPENS (after rollover, bed-time
  and the break-end drain, so the mode is final for this wake) and put back
  when it closes, on every exit. It is therefore scoped to the gesture: C is
  300 ms in Chores mode, in every other wake, and after the gesture. A mode
  toggle cannot happen inside the gesture (A is not acted on there). The
  residual: C taps made before the gesture opens (during a rollover window)
  were accepted at 300 ms and a second tap in that period may be refused.
- **Count display is HIGHPRI** (quiet hours do not mute it), like the chore strip.
- **Colour: magenta (25,0,25).** Existing: timer states green/amber/red/cyan-blue/white,
  chore green/red, countdown light green (20,60,20), sync pixel blue/green/red.
- **Mapping reuse.** `neopixel_status_binary4` is STATUS class and would be
  muted in quiet hours, and is not host-testable. Its shift is moved, unchanged,
  into `neopixel_binary4_pixel_lit()` (neopixel.h); `neopixel.c` and
  `status_led_swap_count_for` both call it: one shift in the tree.
- **Kconfig host fallbacks.** The brief asked for host fallbacks; the chore knobs
  deliberately have none (a renamed symbol must break the firmware build), and
  test/CMakeLists.txt supplies non-default values. The swap knobs follow the
  chore pattern.
