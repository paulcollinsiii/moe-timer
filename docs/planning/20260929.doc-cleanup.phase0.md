# Documentation cleanup — Phase 0

Companion to [20260929.doc-cleanup.md](20260929.doc-cleanup.md). This is the
coordination artifact the owner signs off before Phase 2 fans out.

Status: **draft for owner sign-off.** Nothing in `docs/` has moved yet.

## How to read this

- **Part A** gives every source passage exactly one primary destination.
  A Phase 2 stream owns the rows whose destination is in its files.
- **Part B** sorts the 40 smoke-test entries (1–39 plus 25a) into host-tested,
  host-testable, and hardware-only.
- **Part C** holds the system invariant table (it goes into `architecture.md`)
  and the development rules (they stay in `.claude/CLAUDE.md`).
- **Part D** holds a brief per target doc, the layout changes proposed, the
  conflicts found, and the questions for the owner.

Conventions:
- Row IDs: `A-nn` architecture.md, `P-nn` ProductOverview.md, `H-nn`
  home_assistant.md, `D-nn` developer_setup.md, `#n` smoke-test item,
  `HCn` hardware-checklist item, `Gn` host-test gap, `Sn` system invariant,
  `Cn` conflict.
- `Lnnn` is the line in the source doc at `4e871da`.
- Destinations are relative to `docs/`. `arch/X` is not used; paths are spelled out.
- "delete: duplicate of `<path>:<symbol>`" means the point already lives in that
  code comment. I opened each one; the Phase 2 writer should still confirm the
  specific point is there before cutting.
- "STALE" in Notes means the source prose is wrong today; the evidence is given.
  The writer carries forward the corrected fact, never the prose.

Proposed final list:

- **Pure C**: no C++ translation units.
- **IDF 6 component names** go in `REQUIRES`: `main` needs `esp_driver_gpio`,
  `esp_driver_dac` and `esp_driver_rmt`; `components/ssd1680` needs
  `esp_driver_spi` and `esp_driver_gpio`. The `driver` umbrella no longer pulls
  them in.
- **`timer_defs_install()` runs every boot before any `timer_*` call that
  reads a definition** (only `timer_rtc_state_guard()` precedes it). Host
  tests inject their own table with `timer_set_defs()`.
- *(new)* **`APP_MODE_TIMERS` must stay 0**: `timer_reset`'s memset is how the
  rollover returns the device to Timers (`include/timer.h`, the comment above
  `app_mode_t`).
- **Keep refresh policy and panel protection separate.** Partial/full cadence
  is `display.c` policy; BUSY serialization and the 1 s guard belong to the
  ssd1680 driver. Don't merge them.
- **Display goldens are the layout contract.** Regenerate them
  (`MAGTAG_WRITE_GOLDEN=1`) only for an intentional layout change, never to
  pass an unexpected diff. The flag rewrites every golden, so check out the
  ones you did not mean to change.
- *(new)* **Bump the layout version on any layout change.** That is
  `TIMER_SNAPSHOT_VERSION` for `timer_snapshot_t` and `RTC_STATE_VERSION` for
  `rtc_state_t` (`include/timer.h` already demands this).
- *(new)* **A new or renamed HA entity bumps `STATS_JSON_DISC_SCHEMA_VER`**
  (`include/stats_json.h`), or HA never sees it.
- *(new)* **A field settable from an HA entity must also be expressible in the
  bulk config document**, or the next document apply destroys it (A-70).
- Link line: "System invariants (the NeoPixel gate, clock steps and expiry,
  locks, OTA) are in `docs/architecture.md#system-invariants`."
