# Sprite variants (stream E) - working notes

Branch `feat/sprite-variants` from `integration` (fd25fda).

## Decisions

- File naming: `<slot>.png` is variant 0, `<slot>.<n>.png` (n >= 1, no
  leading zeros, no gap) are variants 1.. in both `tools/sprites/` and
  `sprites.local/`. Largest n is 254 (the index and count are `uint8_t`).
- Size: every variant must equal its slot's base image size; refused with the
  file and both sizes.
- Override semantics: per file, by number. `<slot>.png` replaces variant 0,
  `<slot>.<n>.png` replaces the template's variant n or adds it. Template
  variants the override dir does not name stay. Reason: dropping
  `sprites.local/charge.1.png` is "give me a second picture", and that must
  not silently delete the template art; the existing "same name replaces"
  rule is unchanged for the base. Numbering is checked after the merge.
- Gaps are refused (after the merge, so an override can fill one).
- Header is override-independent: the count is `const unsigned` defined in
  the C, not a macro.
- Pick state: a 2-byte `sprite_pick_t` owned by display.c as `RTC_DATA_ATTR`
  (same shape as `s_partial_count` / `s_takeover_on_panel`: display-owned RTC
  state, logic in a pure module), NOT in `rtc_state_t`. So no
  `RTC_STATE_VERSION` bump and no change to the NVS snapshot. `timer_reset`
  (day rollover) memsets `g_rtc_state`; a pick stored there would be redrawn
  at midnight for no reason.
- Validation instead of a version: the state is checked against the current
  lock and count on every call, so zeroed RTC (esp_restart), another image's
  bytes (OTA failsafe sleep) and a shrunken count all end in a redraw.
- No "avoid last episode's variant": the previous variant is not kept across
  a lock change, and uniform is allowed by the plan.
- Screens take the picked `const sprite_t *` (not an index): lets a render
  test hand in a hand-built second variant with no file; display.c resolves
  index -> pointer with `sprite_variant()` (falls back to variant 0).
- "Lock kind changed" had no existing decision point. display.c is the one
  place every lock paint goes through, so the pick is made there.
  Episode ends on `build_for_state` painting a non-break screen. Other
  takeovers (OTA, setup, sync failed, no clock, config error) neither start
  nor end an episode.

## Done

- Generator + tests, pick module + tests, screens + display.c wiring +
  render tests (a band variant built in memory; no new golden, none
  regenerated), docs. Host suites 55/55, firmware builds (1,362,832 B vs
  baseline 1,362,480 B), sdkconfig unchanged.

## Not verified

- On-device behaviour (no hardware run): that the pick survives a real deep
  sleep. The host tests cover the pick logic and the render path only;
  display.c is not host-compiled.
- The firmware build uses the owner's sprites.local/ (one variant per
  slot), so the multi-variant table was compiled with gcc on the host only.

## Review fixes

Done (all committed on feat/sprite-variants):

- M1/M2/M3/m1: the pick is per lock (`sprite_pick_t.held[lock]`, variant + 1,
  0 = no episode). Episodes start lazily at the first paint and end only
  through `display_lock_art_end()` (display.h, a forward to `sprite_pick_end`).
  `build_for_state` no longer ends anything. End sites: charge release and
  both bed-time releases in lock_gate.c; wake_flow_break_end() and
  wake_flow_report_undrained_break_end() (the two places a break end is
  consumed); the break START in wake_flow_maybe_start_break (a new break is a
  new episode, which also covers a break wiped by a day rollover with no end
  edge, so timer_reset needs no hook); the time's-up alert after
  paint_current_state_full() supersedes its screen.
- Decision: the validity flag is folded into the byte (variant + 1) rather
  than a separate flag array. Zero is no episode; stale bytes are validated
  against the count on every read.
- Decision: the test stubs count end calls in their own arrays, not in the
  suites' event logs, because several older cases pin the log's exact length.
- m3: boundary tests (stored variant == count, count - 1); mutation `<` to
  `<=` in sprite_pick.c failed two tests, restored.
- m4: override size is refused at .1, .2 and .3; mutation "n < 2 and size
  differs" failed the new test, restored.
- m5: CMake strips `(\.[0-9]+)?\.png` and de-duplicates; doc matches.
- m6/m7/m8/m2: docs, comments, generator prose and the generated header note.

Not covered by a host test: display.c itself (not host-compiled), so the
glue (`display_lock_art_end` forward, `lock_art`) is checked only by the
firmware build; bench: hold a lock across a network window with an expiry
alert and confirm the art does not change.
