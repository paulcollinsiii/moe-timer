## Survey: what is drawn at each size

All font references are in `main/display_screens.c` (the only file that names
a font). `LV_FONT_DEFAULT` is Montserrat 12 (`sdkconfig.defaults`), but every
label sets its font explicitly through `make_label()`, so the default font
only serves LVGL internals.

| Size | Call sites (screens) | Text drawn | Code points kept |
|------|----------------------|------------|------------------|
| 12 | header date/time, last-sync, status hint, battery + version row, mode line, state word, button-row labels, locked-block label, setup text, OTA lines, no-clock / config-error lines | user text (timer name, hint, firmware version, SSID) | `0x20-0x7E`, `0xB0`, `0x2022` |
| 16 | break chip, "Charge Me!!!", break chore line / swap hint / bottom row, chore screen title and rows, config-error line, no-clock lines | user text (chore names, swap hint) | `0x20-0x7E`, `0xB0`, `0x2022` |
| 18 | "SCREEN BREAK", bedtime line, OTA version lines, setup host and AP password, retry line | AP password, page host, version strings | `0x20-0x7E`, `0xB0`, `0x2022` |
| 28 | remaining time, "TIME'S", "No sync - check WiFi", "No Clock", "Charge\nme!", "Bed Time", "Goodnight!", "Config Error", "Updating Firmware", "Release to"/"enter setup", the four setup-end titles | string literals only, plus `%02ld:%02ld:%02ld` | 40 code points: `0x20-0x21,0x27,0x2D,0x30-0x3A,0x42-0x43,0x45-0x47,0x49,0x4D-0x4E,0x52-0x55,0x57,0x61,0x63-0x69,0x6B-0x70,0x72-0x75,0x77,0x79` |
| 48 | break countdown (`%ld:%02ld[:%02ld]`), "UP!" | digits, colon, "UP!" | `0x20-0x21,0x30-0x3A,0x50,0x55` |

Verified, not assumed: 48 draws only the countdown and the literal `UP!`. 28
draws no user text (its one computed string is the remaining time; every other
28 label is a literal, listed above). 12/16/18 take user text, so they keep
the whole printable ASCII range, plus the two non-ASCII points the stock builds
carry (degree sign, bullet) so a timer name using them draws as it does today.
No drawn string in `main/` contains a non-ASCII byte other than the
`LV_SYMBOL_*` glyphs (the only non-ASCII bytes in the sources are in comments).

Symbols (`LV_SYMBOL_*`, FontAwesome private-use code points): at 12, battery
empty/1/2/3/full (`0xF244..0xF240`), play `0xF04B`, pause `0xF04C`, right
`0xF054`, refresh `0xF021`, tick `0xF00C`; at 16, tick, right, refresh. None
at 18, 28 or 48. The stock fonts carry about 60 symbols per size.

The single source of these sets is `include/ui_font_ranges.h`;
`test_ui_fonts` re-derives the 28/48 literals and the symbol uses from
`display_screens.c` and fails if a label outgrows its range.

## Tool check (`lv_font_conv`)

Pinned: `npx lv_font_conv@1.5.3` (latest on npm, 2026-11). Read from its
README and source (`lib/collect_font_data.js`, `lib/freetype/index.js`):

- Inputs: TTF, OTF, WOFF (README adds WOFF2). Every input is parsed with
  opentype.js and rendered with FreeType (wasm), so **BDF and PCF are not
  accepted**. A bitmap-strike font is usable only as a TTF/OTF that carries the
  strikes or on-grid outlines; FreeType loads an embedded strike when the
  requested size matches (Terminus TTF has them).
- `--bpp 1` sets FreeType's **monochrome target** (`FT_LOAD_TARGET_MONO`):
  no anti-aliasing, real hinted rasterisation. **`--autohint-strong` is only
  read in the anti-aliased branch, so it has no effect at 1 bpp.** The plan's
  "Montserrat at 1 bpp with strong autohinting" is therefore the default
  (`FORCE_AUTOHINT`); the one switch that matters is `--autohint-off`, which
  uses the font's own TrueType bytecode instead of FreeType's autohinter.
  `--lcd`/`--lcd-v` are irrelevant (and incompatible with 1 bpp mono).
- Used: `--no-compress --no-prefilter` (the build has
  `LV_USE_FONT_COMPRESSED` unset), `--format lvgl`, `--lv-font-name`,
  `--force-fast-kern-format` (what LVGL's own fonts use), `-r` ranges,
  per-font `--font ... -r ...` to merge the FontAwesome symbols.
  `--lv-include` is not needed: the generated `#include "lvgl/lvgl.h"` is
  satisfied by `LV_LVGL_H_INCLUDE_SIMPLE`, set for these sources (main's
  CMakeLists, the host CMake).
- Compiles against the project's LVGL 9.5.0 (`dependencies.lock`): all 15
  files build in the firmware (`-Wall -Werror`) and on the host.

## Candidates

text. Montserrat Medium and FontAwesome 5 come from the managed LVGL component

Not tried, and why: Unscii (8x8 grid only, no 28/48), Spleen and other

all-caps look), Bold weights. **All three sets are Regular weight, so strokes
are 1 px at 12/16 where stock's thresholded 4 bpp looks heavy: weight is the
biggest visible difference from stock and an owner call.** A Bold variant of
`lib` (or of Terminus) is one more entry in `SETS` plus a ~0.4 MB TTF.

## Layout observations (from the contact sheets)

Sheets: `docs/planning/fonts/{stock,mont1,term,lib}.png` (every screen, 3x,
nearest-neighbour; 41 frames incl. three worst-case frames that exist only for
the sheets) and `docs/planning/fonts/compare.png` (eight screens across all
four sets). Frames come from the golden renderer's real LVGL I1 render, so the
thresholding is the device's. I viewed the compare sheet and the per-screen
rows for the lock, error, setup and main screens at 2-3x. Nothing was laid
out again in this phase.

All 1 bpp sets, against stock:
- Heavy look is gone: the stock faces are bold-looking; every candidate is
  regular weight with 1 px stems at 12 px. Crisper and more even, lighter.
- **Break screen (`break_screen*`): "SCREEN BREAK" (18) touches or overlaps
  the 48 px countdown** in `mont1` and `lib` (the glyph tops of "11:40" meet
  the title baseline), and is a pixel or two off in `term`. Stock has a clear
  gap. The fixed `BREAK_TITLE_Y` / `BREAK_COUNTDOWN_Y` assume stock's line
  boxes. This is the one real collision seen.
- Vertical placement moves by 1-4 px on most screens (line heights and
  baselines differ per face): button-row labels, battery row, the 28 px time
  and titles sit a little higher; no clipping seen on the main screen, but the
  clean-band rows in `display.c` were not re-measured (they must be in phase
  2: the 16 pt chip is asserted to stay in rows 3..20).
- `sync_failed` ("No sync - check WiFi", 28): stock and `mont1` fill the whole
  296 px with no margin (as today); `term` and `lib` (Liberation is narrower)
  leave a margin.
- Fit ladders (`display_screens.c`): the locked-block label's ladder was not
  stepped through for every rung. The default rung still fits in all sets on
  `main_chore_gated*` ("0/3 Chores to unlock 60 min" fits in all). The
  `cap_width()` clips on the mode row, OTA, setup and config-error lines were
  not hit by the sheet frames except where noted; the host assertions that
  measure stock metrics fail under the candidates (4 under `mont1`, 5 under
  `term`, 3 under `lib`, counted by the sheet script), which is the checklist
  phase 2 must walk.

`mont1`: same glyph widths as stock, so horizontal fit is identical to today
(including the full-width sync-failed title). Strokes 1 px, uneven at
curves/diagonals at 12 px, but regular; the 28/48 digits are clean. Weak spot:
the thin 12 px text next to heavy progress bars reads lighter than stock.

`term`: monospaced at 12/16/18, so text is wider-spaced and uneven in rhythm
("Last  sync" gaps), but it is the cleanest at 12 px and the narrowest: the
32-char "WWW..." timer name and 20-char chore names fit; the long timer name
overflows into the "(x12" suffix cut by `cap_width` (all sets clip it). The
28/48 sizes are Liberation, so digit style jumps from Terminus to Liberation
between the header and the time. The break screen's 11:40 + title are nearly
touching.

`lib`: narrowest proportional, even stems, best-looking 28/48; 12 px text has
some irregular letter spacing and a slight ragged baseline from bytecode
hinting at 12-16 px ("Mon Jan 05" reads uneven). Title/countdown collide on
the break screen like `mont1`. Fits more than any other set.

## Phase 2 (after the owner picks)

1. Delete the losing sets: `main/fonts/<set>/`, their entries in
   `tools/gen_fonts.py`, the Kconfig options, `ui_fonts.h` branches, the CMake
   foreach, `tools/fonts/<unused face>/`, and the sheets of losers.
2. Make the winner the default (Kconfig choice, or drop the choice and compile
   the font sources unconditionally; `UI_FONT_*` then points at them).
3. Drop the stock Montserrat lines from `sdkconfig.defaults`
   (`CONFIG_LV_FONT_MONTSERRAT_12/16/18/28/48`). `LV_FONT_DEFAULT` must move
   off `CONFIG_LV_FONT_DEFAULT_MONTSERRAT_12` to a font that stays linked, or
   stock 12 stays in the image. Then re-measure the image: the saving only
   appears once stock Montserrat is no longer referenced.
4. **The owner's local `sdkconfig`** still has the `CONFIG_LV_FONT_MONTSERRAT_*`
   values set; hand-edit them off in menuconfig (an existing `sdkconfig` can
   win over `sdkconfig.defaults` for these symbols; use the probe in
   `docs/developer_setup.md`). Never delete `sdkconfig`.
5. Regenerate the goldens once (`MAGTAG_WRITE_GOLDEN=1`, with the chosen set
   as the host default), review every diff, and `git checkout` anything not
   meant to change.
6. Re-check, with the tests that fail under the candidates as the list:
   the break-screen title/countdown gap (`BREAK_TITLE_Y`,
   `BREAK_COUNTDOWN_Y`), the header chip's rows 3..20 vs the `display.c` clean
   bands, `MODE_ROW_MAX_W`/`BATT_ROW_MAX_W` (re-measure against the real font),
   `chores.h`'s 'W' advance comment (names the 16 px glyph table), each rung of
   the locked-block fit ladder, the button-row cell widths, and
   `DISPLAY_CHORE_TICK`.
7. Re-derive `include/ui_font_ranges.h` if any screen text changed.
