# Documentation cleanup — follow-ups

Code work found during the doc cleanup ([plan](20260929.doc-cleanup.md),
[Phase 0](20260929.doc-cleanup.phase0.md)). None of it is in the cleanup's
scope. Each item is a milestone to expand into its own plan when picked up.

## F1 — Credentials live only in `credentials.local.h`

Secrets and URLs must not be able to reach git by way of `sdkconfig`.
- `tools/gen_ha_dashboard.py --mqtt` reads the broker settings from
  `include/credentials.local.h`. Today it reads only `CONFIG_MAGTAG_MQTT_*`
  from an sdkconfig (`parse_sdkconfig`).
- Drop the Kconfig/sdkconfig route for the default MQTT URI/user/password and
  the OTA URL, so `credentials.local.h` is the only source.

Mind the NVS seed fingerprint: changing the seeded strings reseeds on the next
boot, which resets allocations and holidays (Phase 0 C1). Also mind the
hand-set values in existing `sdkconfig` files.

## F2 — LED behavior review

LED semantics have grown by accretion. In Timer mode the pixels report WiFi,
"doing things" and timer state. In Chore mode they mean something else
entirely.
- Decide what each pixel means in each mode. Owner's first inclination: drop
  pixel 3 in Chore mode.
- `MAGTAG_SYNC_LED_FEEDBACK`: decide the production default, and make the
  Kconfig help text match (Phase 0 C16; today it ships on).
- Includes the LED host-test gaps G1 (status-class policy: quiet hours,
  brightness, `binary4` order) and G5 (sync-pixel feedback), since the
  behavior they would pin may change.
- The sync pixel never blinks: it goes blue, then solid green or red, then
  dark (`net_window.c`). The `MAGTAG_SYNC_LED_FEEDBACK` help text still says
  "blinks red three times".
- On an unattended wake with the checklist up, the sync pixel's green above A
  looks like the chore-gate green (`net_window_claim_leds` runs only on
  button wakes).
- `wake_flow.c`'s "carried hazard": a minute wake that handles a held press
  can paint the state color over D's chore LED.

To be opened as a separate conversation.

## F4: Firmware behavior found while documenting it

The Phase 2 docs describe each of these as it ships today. Each is a decision:
fix it, or accept it and keep the doc line.
- **No sync back-off.** With WiFi down, every minute wake retries the network
  (`wake_policy_sync_due` records only success): battery drain, and a red
  sync pixel every minute.
- **A held D is dropped** outside the checklist (`wake_flow_pick_latched_press`),
  on the break screen too.
- **Midnight can start up to 2 h late** under the default Bed Time, because
  that lock wakes every 2 hours; under Charge Me! it waits for the lock to
  clear.
- **No OTA check when No Clock clears** (`lock_gate.c`).
- **Bulk-document validation asymmetry.** The document checks only the length
  of `name`, `tz` and timer names; the HA controls also refuse quotes,
  backslashes and control characters.
- **Dead code:** `display_sync_failed()` is declared and never called.

## F6: Pin the managed components

`main/idf_component.yml` allows `lvgl/lvgl: "^9.3.0"` and `espressif/mqtt:
"^1.0.0"`, and `dependencies.lock` is gitignored, so each fresh checkout
resolves the newest release. The doc-cleanup worktree got LVGL 9.6.0~1 and
mqtt 1.1.0 (the main checkout has 9.5.0 and 1.0.0). LVGL 9.6's new defaults
(e.g. `LV_FONT_UNSCII_8`) tripped the 85 % slot guard.
- Commit `dependencies.lock` (Espressif's advice for applications), or
  narrow the range to `~9.5.0`.
- Make an LVGL upgrade a deliberate step with a size check and a golden
  check.
