# Chore reward chime — plan

Picks up the **reward sound** deferred in
`implemented/20260909.chorechecklist.md` §9. Owner decisions 2026-10-15.

## The feature

When the press that acks the **last** configured chore lands, the device plays
one short reward jingle, chosen in HA from:

| Option string | Sound | Notes (approx.) |
| --- | --- | --- |
| `Off` (**default**) | silence | — |
| `Zelda secret` | OoT/ALttP "secret discovered" | G5 F#5 D#5 A4 G#4 E5 G#5 C6, ~1 s, last note rings |
| `Mario coin` | coin | B5 (short) → E6 (rings), ~0.6 s |
| `Mario 1-up` | 1-up mushroom | E6 G6 E7 C7 D7 G7, quick even notes, ~0.8 s |

Synthesized note tables in `tones.c` only, never samples (§9: a sampled
original is Nintendo's and stays out of the repo). Recognisable, not
identical — the sine renderer and the small speaker are the limit.

## Decisions — settled, do not re-litigate

1. **This reverses §9's "no NVS tone selection, no HA entity".** The chime is
   an HA select exactly like `tone_expiry` / `tone_break` / `tone_bed`. It
   still gets **no `alert_kind_t`** of its own. Update §9 of the design doc to
   say so and point here.
2. **Its own option list.** The three jingles are NOT added to `tone_id_t` and
   are NOT offered to the expiry/break/bed selects; those selects, `TONE_COUNT`
   and their stored indices are unchanged. `Off` exists only on this select.
3. **Default `Off`.** Off is the default for a fresh device. (It is not a
   seeded-defaults row: that would change the fingerprint and reseed every
   deployed device.)
4. **Volume is the shared alert volume** (`alert_volume`), so volume 0 mutes it.
5. **It is not gated on quiet hours** (decided 2026-09-22, §9), like the
   alarms: nothing on the device gates audio on quiet hours, only the pixels.
   Say so in a comment at the call site so a check is not added later.
6. **It fires on the release edge from a press, and only there**: the
   `BTN_ACK_RELEASED` return of `button_chore_ack_apply()`. Consequences, each
   one a test:
   - Once per day. Un-ticking and re-ticking the last chore does not replay it
     (`released` is latched).
   - It **does** fire on a day where `chore_free` already covers the whole
     allocation — the kid finished the list; the reward is for the list, not
     the seconds (the release edge goes true with a zero-second grant there).
   - It must **never** fire from a day rollover, a config apply, a chore-list
     change, or a restore — none of those go through the press path. A
     rollover chime would be a bug (owner, 2026-10-15).
   - It fires whether or not the strip is lit (a latched ack drained on a
     non-button wake still releases the day, and the release is never
     replayed, so skipping it would lose the reward for good).

## Shape

- **`tones.c` / `tones.h`** (TDD, host-tested in `test_tones`): a separate
  reward table — e.g. `reward_tone_id_t {REWARD_OFF, REWARD_ZELDA,
  REWARD_COIN, REWARD_1UP, REWARD_COUNT}`, `reward_tones_names[]`, a getter
  returning a `tone_def_t` (NULL for Off), and a clamp. The player needs a way
  to start from a `tone_def_t` rather than a `tone_id_t`; add that without
  changing `tones_player_init()`'s behaviour for existing ids. Test: every
  note is under 8 kHz (16 kHz synth), total durations are in the ranges
  above, Off renders nothing.
- **NVS**: `NVS_KEY_TONE_CHORES` (≤15 chars), `NVS_DEFAULT_TONE_CHORES =
  REWARD_OFF`, `nvs_config_get/set_tone_chores()`; tests in `test_nvs_config`.
- **`audio.c`**: `audio_chores_done_chime()` — reads the selection, Off returns
  without touching the DAC or amp, otherwise one cycle at the shared alert
  volume. Mirrors `cfg_tone()` / `audio_play_tone()`; no new volume logic.
- **`wake_flow.c`**: keep the result of `button_chore_ack_apply()`; on
  `BTN_ACK_RELEASED`, after the strip paint, call the chime (through whatever
  seam `test_wake_flow` already stubs audio with). **`main/main.c` gains no
  line** unless it is a ≤3-line branchless thunk wiring an op, and the
  review must name the CLAUDE.md reason.
- **HA**: a `select` `tone_chores`, name "Chores done tone", in the
  `ha_config.c` FIELDS registry with its own options array; bulk-config field
  in `config_apply.c` (`apply_enum`) per the durability rule; bump
  `STATS_JSON_DISC_SCHEMA_VER` 24 → 25; `tools/gen_ha_dashboard.py` and its
  test; `docs/home_assistant/configuring.md` row.
- **State-JSON ceiling**: `HA_CONFIG_STATE_MAX` is 1536 with a measured
  1164 B worst case. Re-run the measuring test with the new select at its
  longest option and update the figure and every comment that counts the
  selects ("three selects", "1164 B", "372 B") — grep the whole tree.
- **Docs**: `docs/behavior/chores.md` (or wherever chore behaviour lives) gains
  the reward chime, its default Off, and that it is not quiet-hours gated.
