# Stream F2 notes: ESP-IDF v6.0.1 to v6.0.3

Branch `chore/idf-updates`. Scope: IDF only. No managed component moved
(`espressif/mqtt`, `network_provisioning`, `json_generator`, `lvgl` stay);
`dependencies.lock` differs only in its `idf` entry.

1. Confirmed the tag exists: `git ls-remote --tags https://github.com/espressif/esp-idf.git v6.0.3`.
2. Captured the v6.0.1 baseline first (build, `idf.py size`, `idf.py size-components`).
3. `sdkconfig` snapshots in `~/magtag-sdkconfig-snapshots/`: `sdkconfig.pre-f2-bump`,

4. In `~/esp/esp-idf`: `git fetch --depth 1 origin tag v6.0.3`, `git checkout v6.0.3`,
   `git submodule update --init --recursive --depth 1`, `./install.sh esp32s2`.
   `idf.py --version` reports `ESP-IDF v6.0.3`. The Python env name (`idf6.0_py3.10_env`) is unchanged.
5. `.devcontainer/Dockerfile` pin and comment changed to v6.0.3 (same clone flags).
6. `idf.py reconfigure`, then diff against the snapshot (below), then `idf.py build`.

## sdkconfig diff, every line

Neither change predicted by the plan occurred, and both have a reason:

- `CONFIG_ESP_INT_WDT_TIMEOUT_MS` stays 300. The 800 default applies only with
  SPIRAM enabled (`default 800 if SPIRAM` in `esp_system/Kconfig`); this board has none.
  Nothing in `main/`, `components/`, `include/` or `test/` depends on the value.
- `CONFIG_HTTPD_MAX_REQ_BODY_LEN_KB` does not exist in v6.0.3 (it arrives later); absent.

Before the bump, the first `idf.py build` on v6.0.1 already dropped the 8
`CONFIG_MAGTAG_FONT_SET*` lines (their Kconfig belongs to another branch). Expected, not a defect.

Changes made by v6.0.3 itself (`diff sdkconfig.pre-f2-reconf sdkconfig`):

## USB CDC `linker.lf` finding

Re-checked in the v6.0.3 tree (`components/esp_usb_cdc_rom_console`):

- `linker.lf` places the console functions (including `esp_usb_console_interrupt`)
  in noflash only `if ESP_CONSOLE_USB_CDC_SUPPORT_ETS_PRINTF`. It still does not list
  `esp_usb_console_available_for_read` or `esp_usb_console_write_available`,
  which the ISR calls (`usb_console.c:213,218`). The bug is therefore unfixed in v6.0.3.
- `usb_console.c:87`: `ISR_FLAG` is `ESP_INTR_FLAG_IRAM` with the symbol y and `0` with n.
  With n the ISR is masked during cache-off windows, so the fault cannot occur.
- The v6.0.1 link map shows both functions and the ISR in flash text (0x4008xxxx range) with n,
  consistent with the above.

Conclusion: `CONFIG_ESP_CONSOLE_USB_CDC_SUPPORT_ETS_PRINTF=n` stays. The comment at
`sdkconfig.defaults` was rewritten to describe the v6.0.3 state.
