# Swappable lock-screen art — plan

Owner request 2026-10-18: the four lock-screen sprites (charge, time's up,
screen break, bed time; branch `feature/charge-lock-cat`, b7cdebe) must be
swappable by an end user **at compile time**. The owner keeps their own art
(fan art of others' characters, and reference art of unknown licence)
privately; the public repo ships original template art.

## Shape — settled, do not re-litigate

1. **Public templates in `tools/sprites/`**, original art drawn by the
   coordinator, already in the working tree (untracked, commit with the
   implementation): `charge.png` 105×122 (a sad battery holding its plug),
   `timesup.png` 178×124 (a shocked alarm clock, the face cropped by the
   bottom edge), `break.png` 46×52 (a meditating figure with sparkles),
   `bedtime.png` 29×23 (a bed with zzz). The four previous PNGs are
   `git rm`ed (staged).
2. **Private overrides in `sprites.local/`** at the repo root, **gitignored**
   (add `sprites.local/` to `.gitignore`, beside `*.local.h`, with a comment
   in the same voice). Any `<slot>.png` there replaces the template of the
   same name for the firmware build. The owner's four PNGs are already there
   (untracked) under the new names. A `sprites.local/README.md` is NOT
   allowed (the directory is ignored); document the mechanism in
   `docs/developer_setup.md` instead, mirroring how `credentials.local.h` is
   documented.
3. **Slots are fixed: name and size.** Every layout is built around its
   art's size, so an override must match its template exactly (w×h) and must
   name an existing slot. `tools/gen_sprites.py` gains `--override-dir`: it
   merges the override PNGs over the templates and **fails loudly** — naming
   the file, the expected and the actual size — on a size mismatch or an
   unknown name. Mode-1 enforcement stays. The generated header is the same
   with or without overrides (it only declares the four fixed slots).
4. **Neutral slot names everywhere public.** `SPRITE_CHARGE`,
   `SPRITE_TIMESUP`, `SPRITE_BREAK`, `SPRITE_BEDTIME`; rename the layout
   constants that name characters (`CAT_X` → e.g. `CHARGE_ART_X`, `PIKA_X` →
   `TIMESUP_ART_X`, and any others), the test names, test classes
   (`TestCat` …), helpers and messages. Scrub character names (Simon's Cat,
   Pikachu, cat, meditating figure owner art…) from code, comments, tests,
   generated C and the user docs (`docs/behavior/`, `docs/architecture/`,
   `docs/hardware_checklist.md`, `docs/developer_setup.md`). Describe each
   slot by role and size, with the template's look as an example. The dated
   planning docs (`docs/planning/2026*.md`) are historical records: leave
   their text, but **delete from the tree** every image derived from the
   owner's art: `docs/planning/20261018.*.mockup.png`,
   `docs/planning/20261018.*.render.png` and
   `docs/planning/20261018.break-meditate.render/` (they stay in git history;
   that is the owner's call, see "History" below).
5. **Build: committed defaults, generate only when overriding.** The
   committed `main/sprite_data.c` stays, generated from the templates, so a
   plain clone builds with no Python dependency. In `main/CMakeLists.txt`:
   glob `${PROJECT_DIR}/sprites.local/*.png` with `CONFIGURE_DEPENDS`; if
   any exist, add a custom command that runs `uv run tools/gen_sprites.py
   --override-dir sprites.local --c-out <component binary dir>/sprite_data.c`
   (DEPENDS on the templates, the overrides and the generator) and compile
   that file **instead of** `main/sprite_data.c`. If overrides exist and `uv`
   is not found, FATAL_ERROR with a message saying what to install or to
   empty `sprites.local/`. Print one STATUS line naming the overridden
   slots, so a build log shows which art went in. No overrides → unchanged
   build. `--check` keeps comparing the committed C against the templates
   only (overrides never reach the committed file).
6. **Host tests run against the templates**, never the overrides (the test
   CMake compiles the committed `main/sprite_data.c`). Every pinned number
   that described the owner's art (ink counts 2959 / 3241 / 1208 / 226, the
   3-pixel bottom bleed, the 4832 / 3616 scaled counts, band rows that depend
   on art) is re-measured from the templates; Python stays the single source
   and the C comments cite it. The time's-up bleed rule stays (ink on the
   bottom row only inside the sprite's columns; the template's clock is
   cropped by the bottom edge) but its exact count comes from the template.
7. **Goldens: the sprite regions change, nothing else.** Regenerate
   `charge_me`, `timesup`, the six `break_screen*` and `bedtime`; every other
   golden byte-identical (sha256 before/after). The text and layout
   constants do not move; prove it: in each regenerated golden, the pixels
   outside the sprite's box are identical to the previous golden's.
